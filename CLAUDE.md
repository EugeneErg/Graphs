# Карта проекта

Библиотека строит плоскую (планарную) укладку неориентированного графа и рисует
её анимированным SVG: вершины начинают спутанным клубком на окружности и
расходятся в читаемый рисунок без пересечений. Пользователи — те, кому нужно
показать структуру графа картинкой.

Стек: PHP 8.3+ (разработка идёт на 8.4), PHPUnit 10.5, PHPStan уровень max,
php-cs-fixer. Внешних зависимостей в рантайме нет, из расширений нужен `ext-dom`
(только для тестов SVG).

## Каталоги

- `src/Services` — вся логика, каждый сервис без состояния (`readonly`).
- `src/ValueObjects` — неизменяемые значения: грань, дуга, точка, угол, граф, срез.
- `src/Aggregates` — изменяемые сущности: холст заливки, точки сочленения, срез.
- `src/Exceptions` — ошибки входных данных.
- `tests/Cases/Graphs` — графы-фикстуры, возвращают матрицу смежности.
- `examples` — запускаемый пример отрисовки.

## Доменная карта

| Понятие | Где живёт |
| --- | --- |
| граф, связные куски | `GraphService`, `Graph`, `DirectionGraph` |
| заливка по связям | `CanvasService`, `Canvas` |
| точки сочленения, двусвязные ветви | `ArticulationVertexesAggregate`, `TreeService`, `Tree` |
| грань плоской укладки | `Edge` — замкнутый обход, вершина может повторяться |
| поиск граней внутри ветви | `EdgeService`, `IntersectionService` |
| склейка ветвей и достройка до двусвязности | `VertexService::mergeTree` |
| дуги и центры тяжести | `ArcService`, `Arc`, `GravityVertexes` |
| координаты и расслабление | `CoordinateService` |
| плоская геометрия | `GeometryService` |
| планарность движения между кадрами | `MotionService` |
| журнал шагов алгоритма | `Trace`, `Stage`, `StageKind` |
| кадр рассказа | `Scene` |
| отрезанный кусок графа | `Piece`, `Cutout` |
| план разреза целиком | `CutPlan` |
| хореография рассказа | `StoryService` |
| отрисовка и анимация | `SvgService` |
| весь конвейер целиком | `PlanarService` |
| выбор варианта укладки | `SliceAggregate`, `SliceInterface` и его реализации |

## Ключевой поток

`PlanarService::connectionsToSvg`:
связи → `GraphService::createFromConnections` → связные куски →
`TreeService` (двусвязные ветви) → `EdgeService` (грани ветви) →
`VertexService::mergeTree` (склейка) → внешняя грань → `ArcService::createArcs` →
`CoordinateService::getCoordinates` (окружность и дуги) →
`getBarycentricCoordinates` (укладка Татта) → `relaxSteps` (расслабление) →
`SvgService::animate`.

Попутно сервисы дописывают шаги в `Trace`, если он передан: волны заливки,
разбиение на куски, точки сочленения, вырезание ветвей, нарезка на поля,
набор граней, внешняя грань, порядок полей и построение по полю.
`StoryService` превращает журнал в кадры (`Scene`), а `SvgService` рисует кадры.

Разбор всего графа идёт раньше построения: иначе рассказ скакал бы между
разбором одного куска и сборкой другого.

Рядом: `connectionsToCoordinates` отдаёт итоговые координаты,
`connectionsToFrames` — все кадры.

## Что важно знать

- **Планарность — жёсткое требование, и не только в кадрах.** Расслабление
  двигает вершину только внутрь её многоугольника видимости и проверяет, что
  рёбра не пересекли его границу. Но картинка проигрывает переход между кадрами
  по прямой, поэтому два чистых кадра ещё ничего не гарантируют: `MotionService`
  проверяет переход целиком (ориентация тройки движущихся точек — квадратный
  трёхчлен от времени, признак пересечения зависит только от знаков четырёх
  таких трёхчленов), и волна сдвигов укорачивается, пока переход не станет
  чистым. Тесты проверяют и кадры, и переходы между ними.
- **Кадров в картинке ровно столько, сколько нужно.** Промежуточные состояния
  расслабления зрителю не интересны, поэтому кадр выбрасывается всегда, когда
  переход через него остаётся плоским: обычно вся дорога от начальной раскладки
  до расслабленной — один плавный переход.
- **Неудачные попытки в журнал не пишутся:** заливка, накрывшая одну вершину,
  ничего не нашла, и показывать её незачем (`CanvasService::fill`).
- **Ничего не исчезает — всё переезжает.** Граф виден целиком в каждом кадре.
  То, что сейчас не в работе (вершины, ещё не легшие в укладку), приглушается
  и ждёт снаружи рисунка, а не прячется. Приглушение включается заранее, на
  время переезда, а не по прибытии: яркая линия, летящая через рисунок,
  читается как пересечение, которого в укладке нет.
- **Кадр оперирует экземплярами вершин и рёбер, а не вершинами и рёбрами.**
  Когда граф разрезан, общая вершина принадлежит каждому куску, поэтому в кадре
  она встречается несколько раз: ключ экземпляра — вершина плюс номер копии
  (`Scene::vertexKey`), у ребра так же (`Scene::edgeKey`). Все копии заводятся
  заранее и вне разреза стоят поверх оригинала, поэтому раздвоение выглядит как
  расхождение, а не как вспышка.
- **Режем физически, на всех уровнях: куски, ветви, поля.** Отрезанное уезжает
  в сторону целиком (`Piece`), а вершина и ребро на границе раздваиваются —
  у куска не остаётся связи с бывшим соседом. Ребро лежит ровно между двумя
  полями, поэтому из общего куска оно уходит только после второго разреза
  (`StoryService::getCutCount`).
- **Едет только то, что режут.** Весь разрез считается до первого кадра
  (`CutPlan`): место куска на столе и экземпляры его вершин назначаются один
  раз при вырезании и больше не меняются. Если раздавать их на ходу, экземпляр
  в соседних кадрах достаётся разным кускам, и при каждом разрезе едут все —
  паровозик, в котором ничего не разобрать. Тест на это —
  `testCutPieceKeepsItsPlaceForever`.
- **Отрезанное отделяется, а не появляется.** Экземпляры куска заведены с
  самого начала и до разреза лежат поверх своих оригиналов, поэтому набор
  экземпляров одинаков во всех кадрах (`testNothingAppearsOutOfThinAir`), а
  разрез виден как отъезд куска. Заодно копия обязана выглядеть как оригинал:
  цвет и кольцо назначаются по номеру вершины, иначе копия закроет собой
  закрашенный оригинал.
- **То, чего у родителя не осталось, кусок забирает с собой.** Вершина
  раздваивается, только если она ещё нужна остатку; иначе она просто уезжает
  вместе с куском, сохраняя свой экземпляр.
- **У каждого несвязного куска свой стол** (`StoryService::getTables`): кусок
  лежит в середине своего стола, вырезанное из него раскладывается по кругу
  вокруг, и там же он потом собирается. Столы стоят в ряд и не задевают друг
  друга, поэтому два несвязных графа не мешают друг другу ни при нарезке,
  ни при сборке. Стол, с которого всё началось, стоит там же, где лежал клубок.
- **Размер стола меряется по готовой укладке, а не по той, что была до
  расслабления.** Расслабленная укладка шире; если мерить стол по кадру до
  расслабления, в конце куски вылезут на соседний стол и рёбра разных
  графов пересекутся (`testDisconnectedGraphsNeverCross` ловит это).
- **Остаток равномерно распределяется по своему кругу.** Кусок по ходу нарезки
  худеет; если оставлять вершины на прежних местах, от графа остаются редкие
  ошмётки с дырами. Порядок вершин при этом сохраняется — тот же, что в клубке,
  иначе они перемешаются.
- **Все поля уезжают на круг, включая последнее.** Соблазн оставить последнее
  поле в середине стола — чтобы к нему достраивались остальные — портит
  картинку: это поле остаётся лежать в той кривой форме, в какой оно было
  в клубке, и сборка начинается с кривого куска. Пусть уезжает как все, а
  укладка строится с нуля на освободившейся середине.
- **Места на круге раздаются в порядке сборки** (`CutPlan::orderSlots`):
  вырезанное поле сразу ложится туда, откуда его и возьмут. Поэтому шаг
  «порядок полей» отдельного кадра не получает — очередь видна с первого
  разреза, а перестановка уже разложенных кусков была бы лишним движением,
  за которым не уследить.
- **Надрезанное ребро выделено цветом.** Ребро лежит между двумя полями и
  режется ровно дважды; после первого разреза его копия в остатке помечается
  (`CutPlan` хранит эти экземпляры, `StoryService::getHalfGroups` красит их).
  Метка появляется в момент разреза, а не когда отрезанное доехало до места:
  разрез — это и есть событие.
- **Отрезанные поля лежат раскрашенными** (`StoryService::getFieldGroups`):
  каждое своим цветом по номеру места, вершины и рёбра. Цвет держится, пока
  поле лежит на столе, и сходит, когда поле возвращается в укладку, — по нему
  видно, что уже собрано, а что ещё ждёт.
- **Вершины куска хранятся в порядке обхода, а не по номерам** (`Piece::ofEdges`
  идёт в глубину, `Piece::ofWalk` — по самому обходу). Кусок потом ложится на
  окружность в этом порядке: соседи оказываются рядом, и вырезанное поле
  выглядит многоугольником, а не звездой из пересечений.
- **За выделением сразу идёт действие, ради которого выделяли.** Кольцо на
  точках сочленения держится до самого разреза по ним, внешняя грань обводится
  — и следующим же кадром ложится на окружность, потому что с неё начинается
  сборка. Выделение, за которым ничего не следует, — ошибка.
- **Подписей в картинке нет.** Что происходит, должно читаться по самому
  происходящему. В кадре от шага остаётся только его вид (`Scene::$kind`) —
  по нему тесты ищут кадр, зрителю он не показывается.
- **Три канала выделения, у каждого один смысл:** цвет — принадлежность группе
  (заливка, кусок, грань), а у ребра — «надрезано один раз из двух»;
  приглушение — «ещё не в работе»;
  кольцо — только точки сочленения и внешняя грань. Кольцо не мигает на волнах
  заливки и на добавлении полей: там и так всё видно по цвету и движению.
- **Разрез накапливается.** Сначала граф распадается на несвязные куски, потом
  каждый кусок — на двусвязные ветви, потом ветви — на поля: разрезанный кусок
  заменяется своими частями, а соседние остаются целыми.
- **Шаг, которому нечего делать, кадра не получает:** связный граф не на что
  разрезать, а если поля и так лежат в нужном порядке, переставлять нечего.
  Поэтому «все этапы видны» проверяется на наборе графов, а не на одном.
- **Журнал не знает координат.** Сервисы пишут только смысл шага; где что
  окажется на картинке, решает `StoryService`. Так геометрия не протекает
  в алгоритм.
- **Грань — замкнутый маршрут, а не простой цикл.** После склейки в точке
  сочленения вершина встречается в грани дважды: `[0,1,2,0,4,5,6]` — нормальная
  грань. Код, который считает грани простыми циклами, сломается.
- **Склейка ветвей достраивает граф до двусвязного.** `VertexService::mergeTree`
  не просто объединяет списки граней: в точках сочленения ветви связываются
  новыми рёбрами, и односвязный граф становится двусвязным. Без этого укладка
  невозможна — всё, что висит на точке сочленения, съезжается в саму точку
  (барицентрическая укладка требует трёхсвязности). Добавленные рёбра в рисунок
  не попадают: рисуется исходный граф, а грани с ними нужны укладке
  и расслаблению.
- **Инвариант набора граней:** граней ровно `E − V + 2` на связный кусок,
  и каждое ребро входит ровно в две грани — но `E` считается **с добавленными
  рёбрами**. Если считать по исходному графу, покажется, что граней лишние,
  и склейку легко «починить» так, что сломается вся укладка.
- **Грань одиночного цикла удваивается:** она ограничивает плоскость с двух
  сторон, поэтому в списке присутствует дважды (`VertexService::withOuterFace`).
- **Срез (`SliceInterface`) — механизм перебора укладок**, а не деталь.
  `getNextValue($size)` возвращает позицию в списке, `0 <= позиция < $size`.
  Кандидаты подаются срезу в порядке предпочтения: например, внешняя грань
  выбирается из граней, отсортированных по убыванию размера.
- **Вершины внешней грани закреплены** и при расслаблении не двигаются — на этом
  держится и планарность, и ограниченность рисунка.
- **Читаемость — это не только расстояние между вершинами.** Вершина, легшая
  на чужое ребро, читается как пересечение, которого нет. Поэтому оценка
  укладки (`CoordinateService::getScore`) берёт минимум из двух величин:
  расстояния между вершинами и расстояния от вершины до чужого ребра.
- **Расслабление идёт в два приёма.** Сначала силы (рёбра тянут, вершины
  отталкиваются, стены своей комнаты отталкивают), потом чистка: каждая вершина
  перебирает направления и отходит туда, где её просвет больше. Шаг чистки
  принимается, только если укладке в целом не стало хуже, — разводя одну пару,
  легко свести другую.
- **Силовая модель раскачивается**, поэтому `relaxSteps` возвращает не последнее
  состояние, а лучшее из встреченных по этой оценке. Результат не бывает хуже
  начального.
- **Масштаб задаёт `SvgService`**, а не укладка: картинка растягивается так,
  чтобы ближайшие вершины не слипались и чтобы вершина не налезала на чужое
  ребро. Ради этого всё и делалось — рисунок должен читаться без приближения.
  Расстояние между вершинами меряется между разными вершинами: экземпляры одной
  лежат друг на друге, и если считать их, масштабировать будет нечего.
- **`getNeighbours` отдаёт соседа и ключом, и значением.** Значения нужны обходу
  соседей, ключи — `MotionService::getEdges`. Если оставить только значения,
  список рёбер молча получится из индексов, и сторож планарности волны будет
  сторожить выдуманный граф.
- **Рассказ проигрывается один раз и замирает** на готовой укладке
  (`repeatCount="1"`, `fill="freeze"`): смотреть на результат интереснее, чем
  на вечно начинающийся заново рассказ. И первый кадр расслабления почти
  не держится — он повторяет собранную укладку, и пауза перед самым
  интересным была бы лишней.
- **Цвет ребра задаётся классом, а не атрибутом.** Правило стиля перебивает
  и presentation-атрибут, и его SMIL-анимацию, а переменная темы внутри
  значений анимации не работает вовсе (получается чёрный). Поэтому
  анимируется `class`, а цвета остаются в CSS и переживают тёмную тему.
- Анимация — теги SMIL `animate` и `animateTransform` внутри документа.
  Ни скриптов, ни внешних ссылок: SVG самодостаточен.
- Сервисы ничего не пишут на диск и ничего не печатают.

## Команды

```bash
composer install
composer test                       # все тесты
composer test -- --filter testRelax # один тест
composer stan                       # phpstan, уровень max
composer cs                         # php-cs-fixer, проверка
composer cs:fix                     # php-cs-fixer, правка
php examples/render.php Big1 > big1.svg
```

Переменных окружения проект не требует.
